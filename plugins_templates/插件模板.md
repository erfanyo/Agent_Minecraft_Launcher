# 启动器插件模板(给「AI 生成新模块」用)

> 这是让 **用户的 AI** 照着生成一个新启动器模块的**最小模板**。把这套格式喂给 AI 即可。
> 插件 = `plugins/<名字>.py`,提供 `register(api)` 函数,启动时被静态装载。
> 运行时数据放启动器私有目录 `AMCL/`(tools/plugins 说明见 `规划-汇总.md §6`)。
> 可交给 AI / 手工 `plugins/` 目录里新建,设置→插件 里能看到并可启禁。

## 0. 三行上手

```python
PLUGIN_ID = "my_plugin"                # 插件名(唯一,作为 id 前缀)
PLUGIN_NAME = "我的插件"               # 显示名
PLUGIN_DESCRIPTION = "一句话说明这是干嘛的"

def register(api):
    ...
```

## 1. 四类注册点(全部为可选;要哪个写哪个)

### 1a. AI 工具(让 AI 能调用一个新动作)
```python
def register(api):
    def my_action(args: dict) -> str:
        # args 是 AI 传的参数字典;返回字符串(文本结果回给 AI)
        return f"处理了 {args.get('x')}"

    api.register_tool(
        name="do_thing",                  # 工具名 → 实际为 my_plugin__do_thing
        description="描述这个工具干嘛,给 AI 看(决定它何时调用)",
        parameters={
            "type": "object",
            "properties": {"x": {"type": "string", "description": "参数说明"}},
            "required": [],               # 必填参数名列表
        },
        handler=my_action,
    )
```

### 1b. GUI 页面(注册一个新章节/页面)
```python
def register(api):
    def build_page():
        from PySide6.QtWidgets import QLabel, QVBoxLayout, QWidget
        w = QWidget()
        lay = QVBoxLayout(w)
        lay.addWidget(QLabel("我的页面内容"))
        return w

    api.register_gui_page(label="我的页面", build_fn=build_page)
```

### 1c. 设置项(登记一个可开关/选择项,占位)
```python
def register(api):
    api.register_setting(
        key="greeting", description="打招呼文案", default="你好",
        choices=None,   # 可选:["A","B"] 固定候选
    )
```

### 1d. 技能(Skill 子类:挂游戏生命周期 + 给 AI 提示)
```python
def register(api):
    from skill_manager import Skill

    class MySkill(Skill):
        id = "my_plugin_skill"
        name = "我的技能"
        description = "说明"
        category = "运行辅助"
        default_enabled = True

        def ai_hint(self) -> str:      # 注入 AI 系统提示,指导 AI 行为
            return "【我的技能】启用后 AI 要……"
        # 可加生命周期钩子:on_game_start(process, instance_id) / on_game_log(line) / on_game_stop(exit_code)

    api.register_skill(MySkill)
```

## 2. 核心原则

- **核心组件不插件化**:启动 / 实例 / 下载 / 设置 / AI 这些底座保留在核心代码里,不动。
  插件只承载**非核心/可选/锦上添花**的功能(如 联机方案、Mod 依赖网络、额外工具/页面)。
- **静态加载**:改动插件要重启启动器生效(不做热加载,简单稳)。
- **启注定** `settings["plugins_disabled"]`:设置→插件 对话框里取消勾选 → 下次启动跳过该插件。
- **安全**:插件是本地可信代码,与 AI 工具/技能同等级;未来可加权限/沙箱(复用 ai_actions)。

## 2b. 插件许可证约定(重要)

> 启动器本体走 **AGPL-3.0**。对于插件,分两种情况:

| 插件来源 | 许可 | 说明 |
|---|---|---|
| **你自己(启动器作者)写的插件** | 随启动器 **AGPL-3.0**(以后可能换 **GPL**) | 和你发布的核心一起走强 copyleft |
| **第三方作者写的插件** | **由各作者自己定**(可 MIT/Apache/闭源…) | 启动器只是"加载并调用"它,不强制它 AGPL |

**为什么第三方插件不必 AGPL**:因为插件是**独立作品(mere aggregation)**——它通过本模板的公开 API(`register(api)`)**注册内容**,启动器只做"调用方",**不要求插件深入启动器内部实现**、不修改核心、不共享深层代码。这样的插件属于独立作品,其许可证由作者自定,AGPL 的传播性不会"传染"到它。

**如何守住这条分界线(插件作者 / 你的 AI 生成插件时都要遵守)**:
1. 插件**只依赖 `api`(公开注册接口)和 PySide6 / 启动器已公开的少量工具函数**,别 import 启动器内部模块改行为;
2. 插件**不改** `plugin_manager` 之外的任何启动器代码、不 monkeypatch 核心类;
3. 若插件确实**修改/派生**了启动器核心(如复刻核心逻辑、改内部实现),那它**必须 AGPL**。


## 3. 目录与交付

- 插件放 `plugins/`(启动器私有数据,gitignore)。
- **随发行分发的示例/产品数据**放仓库根 `plugins_templates/`(如本文件,Git 跟踪)。
- 新功能落地前先问一句"**文件放哪**":插件自身状态/缓存 → `AMCL/`;产品数据 → 仓库根。
