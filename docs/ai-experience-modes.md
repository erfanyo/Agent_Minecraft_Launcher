# AI 回答与操作确认模式

AI 设置新增两个彼此独立的选项。

## 回答方式

- **普通用户语言（推荐）**：先说明实例能不能玩、已经做了什么、功能有什么变化。默认不展示原始日志、哈希、内部工具名和长路径。需要选择时最多给两个按结果描述的选项。
- **技术详情**：保留当前面向排障人员的详细输出，包括日志证据、版本、路径、工具结果和剩余风险。

严重故障需要放弃当前修理路线时，普通语言模式会提出“保留旧实例并创建新的可玩实例”的具体方案。创建工具自身的确认窗口承担这一次询问，模型不得先用 `ask_user` 重复询问。

## 操作确认

- **每项都确认（稳妥）**：保持原行为，每个受控写操作分别展示预览。
- **备份后连续处理（少打断）**：首次修改已有实例前创建完整恢复点；之后，同一轮任务中的可逆日常修复自动继续，直到交付、失败或达到运行预算。

少打断模式仍会单独确认：

- 保留旧实例并创建新的实例或整合包；
- 恢复旧快照；
- 直接改变当前游戏世界；
- 生成启动器插件或修改源码；
- 外部 MCP 写操作和插件声明必须确认的操作。

少打断模式只在桌面 AI 对话中生效。命令行、游戏内 AI 和无确认界面的调用方仍使用逐项确认，文件权限边界始终有效。

自动创建的恢复点和后续动作都会写入本机操作记录。恢复点失败时，实际修改不会开始。

## 跨版本 Mod

自动寻找兼容版本是常驻能力，不提供关闭项。它只在日志或 JAR 内部声明已经证明 Minecraft 版本或加载器不匹配后运行，并且安排在停用原 Mod 之前。一次调用会合并 JAR 身份读取、文件指纹反查和当前实例的严格版本查询；文件及实例环境未变化时直接使用缓存，避免重复读取、搜索和占用模型上下文。

找到精确候选时，使用返回的版本 ID 替换并保留旧文件；找不到安全候选时，普通用户模式才说明：“这个 Mod 当前不能用，所以已从本次启动中移出。”实际操作使用 `.disabled` 保留原文件，并保留完整恢复点；只有文件确实被删除时才使用“删除”。

未来若加入短时间 Mod 重构能力，应作为独立工具开放：只处理有源码和可复现构建的 Mod，在副本中修改并经过编译、启动和功能验证后才可替换。当前阶段不会直接改写编译后的 JAR。
