# AI 多故障实例测试

云端工具循环不再按 10/12 轮截断，旧 max_rounds 参数仅为调用兼容保留。

结束条件：模型不再提出工具调用（仅代表模型结束，并非游戏验证成功）、用户停止、连续三轮全部工具参数与结果均曾出现、时间预算、上下文预算，或请求异常。默认时间预算 1800 秒，上下文预算为序列化消息 240000 字符；可通过配置 ai_run_timeout_seconds / ai_run_context_chars 调整。字符预算不是精确 token 数，也不保证适合所有模型。

AI 面板“停止任务”是协作取消，在当前请求/工具结束后停止后续调用。网络请求最长读取等待 180 秒；不会强杀写文件的工具。已执行修改不自动撤销。取消、暂停时补齐本轮工具响应，允许后续继续对话。原权限与操作确认保持不变。本地单轮工具路由未改成自主循环。

上下文达到字符预算的 80% 时，先移除历史推理字段，再按需节选旧工具输出的首尾，目标为预算的 65%。保留所有用户消息（含图片）、system 约束、助手正文、完整工具调用参数和调用/响应关系。节选不是语义摘要，中间证据可能被省略；模型须针对缺口重新查询，不能把节选当成成功证明或重放写操作。启用本地记录时，压缩前历史经脱敏写为 context_checkpoint，并记录压缩前后字符数；关闭记录时不写磁盘。压缩后仍超预算才暂停，提示另开对话并交接。此机制不扩大时间预算，也不保证模型会正确完成实际修复。

无正文且无工具调用的响应不再算正常完成：最多重试两次，提高输出额度，并记录 finish_reason。重复空响应会显示明确暂停原因。

第二轮修正：inspect_mod_jar 的原始长元数据可替换成完整结构化声明，身份、必需/可选依赖及冲突不再做首尾截断。快照、恢复、Mod 替换和启停的结果保留完整，以保住回退位置；最近一轮尚未消费的普通工具输出也保留。此类关键数据本身超过硬预算时仍会暂停，不能保证任意大输入都可继续。其他旧工具输出仍可能被节选，不能当作语义总结。结构化解析失败会明确标记 parse_error，不会解释为“无依赖”。

技能管理新增默认启用的“攻坚修理 · 证据与续接”，沿用现有 AI 上下文注入。它要求核对本轮日志、验证 JAR 内部元数据、保留测试约束、逐项可逆修复、观察本轮启动证据，并维护续接账本。技能本身不授予写入权限；用户可关闭。旧“任务拆分”和“自主修复回路”不再因单项失败机械结束整个排查。

沿用“云端工具调用记录”开关。AMCL/ai_runs/<运行ID>.jsonl 增量保存每轮模型消息、工具开始/结果、耗时、调用数、API 返回的 token 用量与结束原因。写入前使用现有脱敏逻辑，不上传；初始图片不写入。原 AMCL/ai_training/cloud_tool_calls.jsonl 汇总继续保留。中断进程后没有 finish 的记录表示运行不完整，不能视为成功。

所有记录的 verification 初始为 not_verified；模型最终答复不是游戏成功证据。尚不自动计算误判数，也不自动建立实例快照。请在测试前另行复制故障实例，保存标准答案；每次从同一份副本测试。示例约束：MC 1.21.1 + NeoForge 不变，不能通过更换环境或大量删除 Mod 宣称修复。

评估时结合日志人工标注：是否进入游戏/世界、保留功能、修改了哪些资源、误判、耗时与工具次数。别把人工损坏但 ZIP 仍合法的 JAR 当成校验通过；文件名也不是 Mod 身份证明。发布训练样本前人工复查个人信息，只有确认有效的修复才作为正样本。
