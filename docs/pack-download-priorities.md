# 整合包获取优先级

## 2026-10-29 当前入口与持久提醒

用户要求恢复“从网盘链接导入（正在努力完善功能）”，现在“导入整合包”按钮展开为“从本地导入”和该浏览器接续入口。此前隐藏的是手工凭证/HTTP 实验界面，该界面仍不恢复。网盘入口先建立 Downloads 接收，再打开分享链接；一个完整候选自动进入安全检查，多候选由用户选择，保留安装确认。可选择其他监视目录，不修改浏览器全局下载设置，不读取 Cookie。

导入实例创建后持久保存恢复信息，失败时保留校验绑定的恢复压缩包（含智能导入的临时组件），成功后清除未完成提醒。启动及运行期间从实例记录/旧 `_imports` 标记恢复状态球红色 ×，其他任务完成、关闭详情标签、重启均不清除。状态页可补齐并重试或手动忽略；忽略只隐藏提示，不删除未完成标记、不把实例标为完整，新一次显式导入失败会重新提醒。仍未完成的实例继续不进入正常可启动列表。

恢复操作核对源包 SHA256，复用 Downloads 中 SHA1 匹配的缺失文件，按原游戏目录和固定实例 ID 重试；源包不可用或变化时提示从本地重新导入，不执行任意命令。不在启动时自动运行安装器。以下旧入口描述保留为研究历史，以本节和后续进度记录为准。

## 2026-10-27 导入前检查接续

本地文件选择、拖入 ZIP 和智能导入入口新增后台预检查。归档检查覆盖完整性、路径、链接、大小与压缩比；单一 ZIP 成员的外包装最多拆两层，每层重新检查并核对哈希。内层复制到原包旁独立 `AMCL-import-*` 目录，原包不移动、不删除；多个候选或更多层嵌套不自动猜选。

设置的“整合包安全检查”恢复显示原有自动杀毒开关，保留用户已关闭的偏好。开启时尝试现有 Defender/ESET 只检测接口，未接入的杀软、关闭或无法完成扫描会弹可恢复的说明；疑似威胁状态停止此次导入，不能用另一个引擎的无检出覆盖。文件在检查期间改变则拒绝继续。

检查后仍需用户确认，随后进入原有经典导入配置或智能导入预览。提示明确结构检查不保证无恶意、后续下载模组不在原包扫描范围内；不会启动游戏或执行包内启动脚本，安装官方加载器可能运行其安装程序。文件夹/TAR 保留原有严格扫描，暂未接入自动杀毒。浏览器自动接收、AI 直接工具调用、资源页下载及独立服务端入口未在本次统一接续范围内，不宣称所有入口都已有弹窗。

真实 NovaEngineering 样本预览发现并修复：根部已有整合包清单时，不能把 overrides 子目录当成整个客户端，否则会丢失 252 项模组引用及运行环境声明。修复后预览保留根部清单，识别 Minecraft 1.12.2 / Forge 14.23.5.2860；只生成预览，未实际创建实例或下载依赖。

资源页和 AI 的 Modrinth / CurseForge 整合包下载保存在当前游戏目录的 `downloads/modpacks/<时间-随机标识>/`。每次下载独立建目录，避免同名包覆盖；导入成功和失败均保留原 ZIP/MRPACK，结果提示显示原文件位置。本地手工导入继续读取原文件，不挪动它。

## 网盘接入路线

1. HTTP 优先：分别适配分享解析、分页目录、文件候选和下载请求。只有已实现且验证的网盘适配器才能调用；现有匿名 `read_public_webpage` 不是通用网盘 API 客户端，不扩大它的 Cookie、自定义请求头或下载权限。必要的登录授权或无 HTTP 适配时，再使用 Playwright 扩展连接用户浏览器。
2. 下载和导入分为两个阶段。接收器只从约定的浏览器输出目录取得完整下载；验证归档、大小和安全扫描后，将原包复制到永久下载目录。不能仅靠文件名或短暂大小稳定判断下载完成。
3. 本地接收器返回固定任务 ID、文件名、大小、校验值、原包位置及扫描结果。AI 不传任意目标路径，不读取浏览器 Cookie，也不执行页面生成的 cURL / shell 命令。
4. 原包可直接打开位置以便分享；用户确认导入后再调用现有导入流程。导入失败时从原包重试，无需重新下载。普通资源页明确点击下载整合包的既有流程继续下载并导入，但保留原包。
5. LinkSwift 是重点研究的兼容性参考和可选页面工具。它的网盘支持不等于所有分享页直接可下载，例如上游记录已经移除百度分享页下载代码。其开放平台与网页内部接口混用，独立 HTTP 适配也可能需要令牌、Cookie 或请求签名；不借用其应用身份或自动导出浏览器凭据。需要授权或客户端时明确交给用户接续。

## 2026-10-26 HTTP 适配进展

`cloud_drives.py` 提供两个助手工具：`browse_cloud_share` 与 `download_cloud_archive`。模型不接受 Cookie、Authorization、自定义 API 地址、请求头或下载路径参数。支持域名解析、公开 DNS 校验并固定连接 IP、TLS 校验、API 固定域名、有限响应和有界分页。返回的下载 URL 不交给模型；跳转重新验证公开 HTTPS 地址，跨主机不转发 Cookie，Authorization 不发送到下载 CDN。

设置 → AI 助手 → 网盘 HTTP 下载 → 登录与连接网盘，可打开官网登录并按说明从开发者工具取得本人会话凭证。凭证由本机遮蔽窗口接收，**仅保存在当前进程内存**，不写配置或聊天。重启后需重新连接。此阶段没有自动读取浏览器 Cookie，也没有账号密码登录或第三方应用授权身份复用。

接收器按预期大小和 Content-Length 检查完整性，以 `.part` 写入，完成后发布原包、扫描归档并计算 SHA256；不执行文件或自动导入。原包永久保留，失败和扫描拒绝不冒充成功；完整但扫描拒绝的原文件仍保留并明确标注。每次接收目录写入无凭证的 `download.json`，记录来源、文件名、大小和状态。进程内分享会话最多 32 个、每个 5000 个条目，1 小时失效；重启后需要重新读分享目录，不支持断点续传。

## 文件检查与 Defender

归档结构检查覆盖路径穿越、符号链接、大小与展开限制、压缩比、CRC/完整性等，**不等同于杀毒或代码审计**。新增 `download_review.py` 静态列举程序和脚本，标注 `modpack-candidate` / `server-candidate` / `unknown-archive`；软件发布包不能只因 ZIP 检查通过就当作游戏实例。识别是结构线索，不是兼容性或无恶意证明，JAR 也可能执行代码。

Windows 下载完成后默认尝试系统签名验证过的 `MpCmdRun.exe -Scan -ScanType 3 -File <原包> -DisableRemediation`。只检测、不请求清除，不启用服务、不添加排除项、不还原隔离文件、不改变云端样本提交策略。用户可在网盘设置关闭额外扫描，也可选择已有 ZIP/MRPACK 手工请求检查。报告保存为原包旁的 `.defender-scan.txt`，不把原始命令输出发给模型。

微软说明返回码 0 可能表示未检出或成功处理，因此结果只表述为本次未报告威胁，不说绝对安全；返回码 2 同时可能代表威胁或扫描错误，不能直接说发现病毒。只检测模式告警可能只在命令输出中出现，不一定进入系统UI。无法执行、超时、非零结果均不标记通过。系统实时防护仍可能独立隔离文件；启动器不能承诺原包不受系统策略影响，也不会自动还原或排除。第三方杀软没有统一已接入的扫描接口，暂由用户手动调用。

本机只读状态核对：Defender 的 AMServiceEnabled、AntivirusEnabled、RealTimeProtectionEnabled 均为 false，AMRunningMode 为 Not running；安全中心只登记 Windows Defender，未列出其他杀软。对本地无害测试 ZIP 的命令调用返回 2，日志明确包含 `Failed with hr = 0x80004005`，**扫描失败，并非发现病毒；未完成一次可确认为通过的杀毒扫描**，没有下载或扫描用户分享中的真实包。

安全审查还收紧了错误输出：仅传递本地编写的 `CloudDriveError` 文案，原生异常可能含下载签名或响应数据，因此对模型统一返回无敏感信息的失败提示。

百度样本目录中有客户端 CurseForge ZIP（21699862 字节）、Cleanroom ZIP（21739818 字节），以及 Java21+ 服务端 ZIP（678072300 字节）。文件名提示外层可能需要解压、且给出公开解压密码；尚未下载，不能确认具体加密层级。当前扫描器明确拒绝加密ZIP，不能冒充已检查内部内容。

# 第三方插件入口

设置 → 插件增加 `third_party_plugins_enabled`，缺省关闭。每次从关闭切换到开启，必须输入 `我已清楚ai制作/第三方插件的风险`。关闭无需输入；启停重启后生效，关闭不会卸载当前进程已执行的代码。

加载器在导入第三方模块之前检查入口；AI 设置工具不能更改入口。核心功能不受影响，现有 MCP 插件继续使用自身开关。AI 生成和远程安装入口不能覆盖内置 MCP 插件。风险确认不是审核、签名验证或 Python 沙箱；本地文件仍需用户信任。

## 下载窗口与登录接续（2026-10-26）

入口：经典“导入整合包 → 从网盘链接获取”、智能导入来源选择，以及“设置 → AI 助手 → 网盘 HTTP 下载”。共用 `CloudDownloadDialog`，独立于是否启用智能导入技能。

流程：粘贴分享文案/链接与可选提取码 → HTTP 浏览分页目录 → 用户选 ZIP/MRPACK → 下载权限检查 → 字节进度/取消 → 原包保存与检查 → 显式进入已有智能导入预览。未识别的软件发布包、扫描拒绝或明确杀毒告警不能直接进入该导入预览；不自动执行脚本、转存或导入。

未登录、验证码、平台限制视作正常接续状态，保留当前列表与所选文件，不无限重试。用户可打开原分享页登录，然后在本机遮蔽窗口显式提供夸克/百度 Cookie 或 123 Authorization；**网页登录不会自动把凭证授予启动器**，当前仍需从开发者工具手工连接，不自动导出浏览器凭证。连接窗口不再把“提供了字符串”称为“连接成功”，有效性以实际请求为准。

如果用户在浏览器完成下载，可直接选择本地 ZIP/MRPACK 复用同一结构与杀毒检查，原文件保留原位置。不能检查的加密ZIP保持拒绝，不冒充扫描通过。HTTP失败后仍可使用这一接续，不强迫安装网盘 App。窗口关闭时取消当前后台请求；分享会话只在进程内保留一小时，重启或过期需重新读取，不提供断点续传。

百度账号下载按本人提供的Cookie访问固定 `pan.baidu.com`，只使用当前分享接口返回的 sign、timestamp、share_id、uk 和 sekey，不执行页面脚本、不生成签名、不借用第三方 OAuth 身份。跨域下载不转发百度账号Cookie。使用完整 surl 与 channel/view_mode 参数后匿名签名申请成功；21 MB 客户端真实文件请求用默认UA和百度下载固定UA各验证一次，均 HTTP 403，未宣称下载成功；无账号登录态，尚无法验证授权后是否放行。

用户明确说明本机使用火绒：系统登记缺失不是“没有第三方杀软”的证据。本机额外 Defender 扫描已关闭，系统/火绒设置未改。提供“打开原包位置 / 用火绒等杀软检查”入口，不猜测命令行或伪造火绒扫描结果。
