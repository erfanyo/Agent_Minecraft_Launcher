# 浏览器助手

AMCL Agent 通过本地 Playwright MCP 连接用户安装的官方 Playwright 扩展。
浏览器工具是通用能力，B站追查只是 `BilibiliResearchGuide` 技能，不是网站硬编码适配器。
公开网页可先使用独立的 [HTTP 读取工具](public-web-reader.md)，无需连接浏览器；
需要登录或动态交互时再使用浏览器。

## 启用

1. 安装官方 Playwright 扩展。
2. 在设置的“浏览器助手”页点击“一键配置 / 修复”。已有 Node.js 22+ 时复用；
   Windows 缺少时自动下载固定版本官方 MSI，核对 SHA256 和 Windows 签名后，通过 UAC 安装。
   仅 MSI 安装提权，npm 和启动器不提权。取消授权或验证失败则停止，不继续安装。
   连接组件固定为 @playwright/mcp@0.0.83，安装时禁用生命周期脚本，不下载 Chromium。
3. 在同一页面粘贴扩展连接令牌，启用连接。
   令牌为本机配置中的明文秘密，输入框隐藏显示，不应分享配置文件。
4. 在 AI 对话中发起网页任务，按扩展提示选择可访问的标签页。

本次源码改动没有重建 dist 中现有 EXE。桥接组件与 Node.js 不随标准单文件包分发，
移动启动器时需要带上 AMCL/runtime/browser-agent；换机器可再次点击一键配置准备 Node.js。
Node.js 是系统依赖，标准启动器包不附带它，不支持自动安装的平台需手工准备 Node.js 22+。

## 能力与边界

- 保留页面快照、查找、截图请求、导航、标签页管理、点击、拖动、悬停、
  输入、选择、键盘、等待、对话框、视口与媒体模拟。
- 本地工具白名单和确认分类不信任远端 readOnlyHint。页面读取无需确认，
  交互经现有执行器逐次确认，并受启动器可写权限约束。连续修复模式不豁免浏览器交互。
- 未开放的上游工具不会挂载；调用层再次检查。禁止脚本执行、上传、配置修改、
  原始网络请求、Cookie 接口和显式本地文件路径。导航仅允许没有内嵌凭据的 HTTP(S)。
- 禁用 WebMCP，避免网页注册额外工具；关闭代码生成；输出目录限制在独立运行组件目录。
- 页面结果标记为不可信数据、脱敏并限长。连接令牌只通过子进程环境传递，
  不进入工具参数或命令行。读取设置也使用统一脱敏；Agent 不可修改 browser_ 配置。
- 这些控制不构成浏览器沙箱。网页跳转和点击可能产生外部效果，用户应检查确认预览，
  并仅连接任务相关标签页。技能提示本身不能可靠判断所有危险按钮。
- 登录、验证码、支付与账户权限交给用户；B站互动需要明确任务授权。
- 当前 MCP 客户端只返回文本内容，截图图片不会作为视觉输入传给模型。
- 下载可由浏览器点击触发，但尚未实现下载完成事件到 AMCL 导入器的自动交接。

## 验证

本地已验证 0.0.83 的 initialize / initialized / tools/list 握手，无需连接用户页面。
安全策略、工具挂载与既有 AI 工具回归测试通过。真实浏览器任务仍需用户在本机设置令牌后验证。

## 2026-10-26 百度分享真实操作测试

用户授权后实际连接既有Edge登录态，进入NovaEngineering-World分享目录，取消全选，定位普通客户端ZIP（页面20.7M），点击该文件行的“下载”，看到包含“普通下载/高速下载”的对话框，再点击“普通下载”。未导出Cookie、未执行页面脚本、未转存、未购买会员或调用网盘客户端。

网页下载弹窗关闭，但MCP尚未返回下载完成事件；检查约定输出目录和系统下载目录中的匹配文件时没有找到原包。**已验证登录态浏览与点击，尚未确认文件成功落地，也未执行导入**。不能把点击成功当成下载成功，需用户确认是否出现下载进度或另存为窗口后继续核对。

发现扩展只装在Edge，而上游默认查找Chrome。源码已增加只读检测：仅核对标准浏览器目录中的官方扩展目录和浏览器可执行文件；仅一个浏览器匹配时传入`PLAYWRIGHT_MCP_EXECUTABLE_PATH`。用户显式环境配置优先，多浏览器同时匹配时不擅自选择。没有读取浏览器配置内容、Cookies或历史记录。新增与现有浏览器测试共12项通过。此修改未重新打包EXE。

完整页面快照有时只返回输出文件链接；显式调用限定深度的`browser_snapshot`可以取得内联内容。页面选择框随悬停动态出现，旧引用可能失效；测试通过重新观察行元素后点击该行专属下载按钮，避免选中整个文件夹。现阶段网盘入口仍保持隐藏。

## 2026-10-29 浏览器文件接收

“导入整合包 → 接收浏览器下载”可显式开启下载目录监视；智能导入来源窗口也有相同入口。默认 Downloads，可选择其他目录但不改浏览器下载设置。仅检测开启后新增/变化的 ZIP/MRPACK，每轮最多检查两个归档，目录枚举上限 10,000 项。原包经完整性与路径限制检查后列出，用户选择后再走导入安全检查；关闭即停止接收，不长期扫描下载目录。

此接收器不读取 Cookie、历史或浏览器配置，不订阅原生下载完成事件，也不推断浏览器安全判定。CRC、哈希及 Windows 写入锁检查用于验证候选，不用文件名或短暂大小稳定作为完成证据。AI 工具自动启动任务和独立浏览器模式仍未接入。
