# 模块拆分：第一批（2026-11-05）

用户安排：分两轮。近期先拆模块，推进可以独立复现和验证的测试；真实联机、人工交互和难以自动验证的玩法等待作者有空逐步调试。UI 重排与正式 QML 迁移仍按线下讨论后的安排推进。

## 本批边界

- `launcher_app/ui/wallpaper_assets.py`：图片来源、预设、缩放、模糊预处理和原图/模糊图缓存。从 `ui_background.py` 抽出，原模块保留公开导出，现有调用兼容。仍使用 QPixmap 和 Widgets 模糊适配器，必须在 GUI 线程运行，不宣称已经异步或已与 Qt Widgets 完全解耦。
- `launcher_app/ui/wallpaper_presenter.py`：只接收明确的显示目标和几何参数，处理普通、设置、AI 专注模式的背景共享；不接收主窗口、不持有其属性。返回共享画布，主窗口保留 dock 兼容状态及信号接线。未来 QML 可使用自己的显示适配器。
- `launcher_app/servers/repair_policy.py`：不依赖 Qt 的服务端修复轮询决策和候选筛选。保留已有策略，不扩大自动停用范围。确认、异步诊断、进程管理、恢复和 UI 反馈仍由既有控制器负责。

本批重点是明确职责和保留行为，没有承诺解决壁纸卡顿，没有迁移正式界面，也没有新增房间收藏或配套包同步。

## 验证范围

本批本机结果：核心回归 955 通过、1 跳过（需主动开启的可见 WebView 测试）、70 个子测试通过；界面回归 132 通过；150% 缩放下的背景、按钮及修复相关测试 18 通过；源码导入冒烟通过。核心测试中本机回环和独立测试进程受限的用例，已在正常权限下复跑完整套件通过。

- 壁纸原图不被模糊修改、强度变化只重建模糊缓存、关闭/切换背景的既有回归。
- 新增普通模式覆盖 dock、设置页不破坏隐藏主画布、专注模式画布尺寸、关闭背景清除在线和专注背景的测试。
- 修复策略新增旧会话隔离、准备阶段不重复处理、进程运行不等于启动完成、依赖错误不作为停用客户端 Mod 证据的测试。
- 既有服务端修复回路测试覆盖确认、重试、失败会话处理和只恢复本轮停用项；不以静态/模拟进程测试替代进入世界及玩法验收。

## 第二轮保留

- 真实联机的重建/重连与网络条件变化。
- 原生桌面输入、背景过渡的观感，以及不同显卡和图形环境。
- 实际进入世界、关键 Mod 功能和存档保留；依赖可复现的反馈样本，不把“启动测试通过”称为完整修复成功。
- 服务端导出人工全流程与实际客户端加入。

后续拆分优先沿下载/导入/启动的业务接口推进，不按文件行数机械拆分，不以传递整个主窗口的方式制造表面模块化。

## 第二批：启动准备与 JVM 参数边界（2026-11-05）

- 原有 `GameLaunchService` 已负责准备 Java、实例文件、身份和启动命令，本批复用它，不重建另一套启动算法。
- `instances/launch_preparation.py` 定义捕获的启动请求，深拷贝本次实例及设置，固定游戏/运行时目录，封装隔离目录选择和定向凭证刷新回写。不访问主窗口或控件，不启动游戏进程。
- `runtime/launch_preparation_controller.py` 负责后台任务生命周期，发出状态、进度、计划、失败和取消信号。禁止重叠请求；游戏目录变化时拒绝计划；取消后晚到的成功结果不能触发游戏启动。控件可在任务启动前接好状态展示。
- `runtime/jvm_options.py` 负责 JVM 参数解析/合并；`ui/jvm_options_editor.py` 负责 Widgets 编辑器。现有 `advanced_launch` 与启动服务的旧导出仍兼容，新的界面调用直接使用编辑器所属模块。
- 主窗口保留已有多开确认、进程检测、任务中心展示和准备完成后的内存选择；进程拉起、游戏日志、游戏内 AI 与退出处理还未拆完。不宣称启动全链路已彻底脱离主窗口，也不宣称整仓库整理完成。

新增隔离测试覆盖配置/实例快照、共享及隔离目录、定向凭证回写、后台准备期间 GUI 响应、大数进度、目录切换、晚到结果取消和失败后重试。测试不连接真实账号、不调用模型、不启动真实游戏。

本批结果：核心全量 958 通过、1 跳过、70 个子测试通过；界面全量 136 通过；150% 缩放下启动准备、实例维护和原有启动任务测试 20 通过；源码导入冒烟及 diff 空白检查通过。未做冻结成品构建、真实游戏启动或进入世界验收。

## 第三批：进程会话与 JVM 开关（2026-11-05）

- `runtime/game_session_controller.py` 接管多开时的进程控制器集合、当前游戏日志路由、后台游戏退出通知和退出启动器时的统一 detach。只依赖 QtCore 和底层进程控制器，不操作主窗口。主窗口通过信号更新界面，不再自行断开/重新连接各子进程信号。
- 第二个游戏启动失败时保留第一个游戏的前台日志及退出路由；原逻辑在新进程启动前已经切走旧信号，此处通过隔离测试验证保留行为。
- JVM 高级选项改为统一开关行，开关只控制展开/收起，不改变已保存 JVM 参数是否应用。实例“跟随全局 JVM 参数”同样改为开关，切换继承不清空编辑内容，沿用 `None` / 空字符串 / 自定义值的保存语义。保留旧 `isChecked` / `setChecked` / `values` 调用兼容。
- 既有窗口、确认、内存建议、启动结果展示、游戏内 AI 和崩溃后联动仍在主窗口，尚未完成全量拆分。

新增测试覆盖多开日志隔离、后台退出不误触发当前游戏退出流程、启动失败保留原路由、detach 不终止游戏；开关折叠保留参数、继承切换、键盘操作及折叠状态校验。深浅主题预览已检查，150% 缩放相关测试 14 通过，界面全量 142 通过，源码导入冒烟通过。

## 第四批：运行实例状态与崩溃证据（2026-11-05）

- `runtime/running_games.py` 接管启动器自有进程与外部扫描结果的合并、窗口出现前的加载状态、窗口关闭后的残留进程过滤，以及检测结果的 PID 创建时间复核。主窗口只消费 PID→实例的结果并更新标签，不再直接维护这套判定算法。依赖可注入，测试不扫描实际玩家进程。
- `instances/crash_diagnostics.py` 从合并后的 `diagnostic_tools.py` 重新成为实际实现模块；旧导入保留兼容。`GameRunEvidence` 保存实际启动目录与起点，不受之后选择或目录设置变化影响。
- 修复旧 `latest.log` 中的崩溃标记可能导致新一轮零退出码被误报的问题：本次诊断按启动时间筛选日志和报告。报告摘要按修改时间选最新，不再仅按文件名字典序选取。未提供起点的旧调用保留历史扫描行为。
- 启动起点在创建进程之前记录，成功后才发布新的运行证据，避免启动后的技能/AI 耗时使早期崩溃证据被误判为旧文件；失败的新启动不会覆盖上一游戏的运行证据。
- 时间和目录筛选不代表完整玩法验证；同一游戏目录被多个同时运行的游戏共用时，日志仍可能互相覆盖。

新增测试覆盖加载/窗口关闭状态、包装进程与实际游戏窗口去重、外部 PID 复用、扫描期间进程退出、自有新进程的窗口历史重置，以及旧日志/旧报告排除、零退出码新崩溃、新报告时间排序、缺失日志和固定目录证据。

本批验证：核心全量 970 通过、1 跳过、70 个子测试通过；界面全量 142 通过；源码导入冒烟、旧崩溃诊断导入兼容及 diff 空白检查通过。没有运行真实游戏或更改玩家实例；真实窗口/玩法验收仍留第二轮。


## 持续整理：下载、实例操作与 AI 边界（2026-11-05）

本轮范围是后续 QML 改造最容易牵连的主窗口业务路径：安装/导入/资源下载、启动准备与运行联动、实例文件操作，以及助手调用核心。页面布局、窗口原生事件、真实多人联机协议及正式 QML 实现不在本轮迁移范围。

### 职责和接口

| 边界 | 输入与输出 | 前端适配 |
| --- | --- | --- |
| 实例安装 | `InstanceCreateJob` 捕获选择、根目录和隔离设置；`run(status, progress)` 创建实例 | 主窗口只提交任务 |
| 资源与整合包 | `ResourceDownloadJob`、`PackDownloadJob`、`ArchiveImportJob` 捕获文件版本和目标；返回文件名或实例 ID | `ResourceDownloadController`、`PackImportController` 处理选择、确认和进度入口 |
| 启动准备 | `LaunchRequest` 捕获实例/设置/目录；生成 `LaunchPlan`，其中保存实际根目录 | `LaunchPreparationController` 负责 QtCore 信号、取消和目录变化保护 |
| 游戏运行 | `GameRuntime` 保存实际进程、实例、根目录和本轮诊断证据 | 主窗口展示状态；`GameSessionController` 路由日志和退出事件 |
| 内存建议 | `assess_launch_memory` 和 `WindowReadinessTracker` 处理估算/稳定可见时间 | `MemoryLaunchController` 通过明确的设置、进程、历史路径接口管理浮窗 |
| 技能/游戏内 AI | `GameIntegration` 接收启动/日志/退出；使用设置和上下文快照 | 主窗口组装回调，不让后台问答读取窗口控件 |
| 实例操作 | `InstanceActions(root)` 执行备份、改名、删除，清理返回成功项和失败项 | `InstanceActionsController` 负责确认、忙碌保护和刷新；失败不再显示删除成功 |
| 一键指令桥 | `CommandSetupRequest` 固定实例、加载器、版本和目标目录 | `CommandSetupController` 展示检测/安装确认；后台不读取主窗口目录 |
| 助手核心 | `tool_catalog` 定义工具/权限集合；`tool_executor` 执行权限校验；`response_router` 调用模型 | `assistant` 留聊天 dock；`settings_forms` 留配置表单；旧导出兼容 |

安装选项归 `instances/install_options.py`；兼容信息归 `resources/resource_compatibility.py`；路径检查归 `core/path_validation.py`；KubeJS 只读扫描归 `instances/kubejs_scripts.py`；联机 Mod 判断归 `runtime/online_mods.py`。旧 UI 模块保留重导出，不再由底层导入对应界面实现。发现的重复路径检查/兼容摘要定义在确认相同后收敛为一份。

原 ZIP/MRPACK 保留在永久下载目录；取消继续作为独立控制流上抛，不能包成一般网络错误。实例删除只作用于固定的 `versions/<id>`；拒绝越界名称和目录链接，不使用运行目录推断删除目标，共享存档/依赖保留。

### 五条验收的证据

1. **职责明确**：上表各模块有一个可描述的职责；主窗口作为装配点连接服务、任务和展示。没有为行数目标把一个操作随意切成多个片段。
2. **显式输入输出**：后台任务捕获实例/设置/目录；业务对象接收必要值、依赖或回调，不接收 MainWindow。Widgets 控制器的 `parent` 只用于窗口所有权/对话框。旧 `make_answerer(win=...)` 兼容入口仍可用，当前启动路径使用上下文快照。
3. **独立测试**：下载取消和原包保留、准备取消与晚到结果、多开失败、诊断时间边界、内存窗口判定、指令桥目录快照、实例删除范围及部分失败均有隔离测试。`test_module_boundaries.py` 还以新进程检查助手/安装核心不加载 QtWidgets。
4. **修改范围集中**：资源版本筛选改 jobs/compatibility；启动取消改 preparation controller；崩溃取证改 evidence；权限改 executor/catalog；对话框和日后 QML 展示不需要复制上述逻辑。新增业务测试直接针对所属模块，不再借 AST 从主窗口抠出下载工作函数执行。
5. **依赖方向稳定**：业务层不导入主窗口和 Widgets；UI 调业务层，main 组装接口。QtCore 任务/信号适配器保留 QtCore 依赖，未来 QML 可复用其信号或另写适配层。兼容重导出允许旧 UI 调用继续工作，不作为新业务代码的依赖入口。

这些判断针对本轮覆盖的路径成立，不代表仓库内每个旧模块都已完成重构。`resources/export_modpack`、`download_tab`、`ai/chat_view` 等现有模块本身仍是界面；名称位置不作为它们能被无界面调用的承诺。主窗口仍保留页面构造、原生窗口事件、导航和少量明确的适配方法，后续换界面时再改装配方式。已有 Widgets 兼容编辑器入口也保留，不影响业务主路径的无界面调用。

### 验证与保留项

- 使用临时目录、假模型/假进程及本机模拟服务，不修改玩家实例，不访问真实账号，不启动 Minecraft。
- 核心和界面套件分进程执行。一次把两套合并到同一进程的尝试触发 Qt 原生绘制崩溃；现行 CI 也是分进程，本轮没有把混跑视作已支持。一次完整核心测试里的宿主关闭状态超时，原测试单独重跑通过，后续全量中未复现。
- 真实进入世界、存档/玩法、账号登录、多人联机、浏览器原生交互、实际显卡流畅度与冻结安装包仍需第二轮人工或专门环境验收。独立业务测试不替代这些验证。


最终本地验证（本轮验收）：核心全量 **1029 通过、1 跳过、70 个子测试通过**；界面全量 **157 通过**。150% 缩放下原 154 项界面全量通过，新增实例操作失败/取消检查随同该控制器的 7 项测试另行通过。源码导入冒烟、编译检查、diff 空白检查通过。另做提取模块的名称引用检查，修正云端路由漏导入的 `cast`，并以模拟回复验证云端结果和强制工具挂载；没有调用真实模型。

停止依据：本轮覆盖路径的五条判断已有代码边界和测试证据，故在五小时上限之前结束本轮。后续按新增功能或实际耦合继续拆分，不为减少行数继续切碎界面装配。
