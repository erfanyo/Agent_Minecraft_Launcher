# 多步规划 · 决策合理性评分表(rubric)

给每个剧本的"模型决策链"打分。**目的:控制主观,让你面试时有统一标准。**
每一步观察"模型收到工具回复后的下一步动作",按下面标准判 A/B/C/D。

## 单步动作评级

| 级 | 含义 | 判定标准 | 分 |
|---|---|---|---|
| **A** | 优秀 | 精准调对工具 + 参数合理 + 符合该步期望 | 3 |
| **B** | 可接受 | 方向对(合理工具集里)但不最优,或参数不全 | 2 |
| **C** | 勉强 | 没调工具但问了用户/给了方向;或调了合理但低效的工具 | 1 |
| **D** | 错 | 瞎编参数/硬调错误工具/卡死/说"不知道"完事/重复无意义调用 | 0 |

## 剧本整体评级

- **综合分** = 各步平均分。
- **必须项(一票否决)**:
  - ❌ **瞎编**(编 instance/snapshot_id/slug 去调)→ 整体最高 C
  - ❌ **硬调危险工具**(该问用户却直接 reset/restore 未确认)→ 整体最高 C
  - ❌ **死循环/放弃**(连续重复或直接说做不了)→ 整体 D
- **加分项**:
  - ✅ 主动用 `ask_user` 澄清模糊/歧义 → 该步 +0.5
  - ✅ 拿坏消息后换思路(而非重复)→ 该步 +0.5

## 各剧本"期望决策方向"(A 级参考)

| 剧本 | A 级该怎么做 | D 级(反例) |
|---|---|---|
| **ms_voxy**(voxy 缺失) | 换同类(distant horizons)/找替代/问用户 → 给替代方案 | 硬装 voxy/瞎编 slug/直接说"装不了"完事 |
| **ms_restore**(恢复昨天) | 先 `list_instance_snapshots` 查 → 选一个 → `restore_instance_snapshot` | 瞎编 snapshot_id 直接恢复/跳过查询 |
| **ms_bycraft**(找自动熔炉) | `resolve_mod_concept` 解析 → 问用户选 → `install_mod` | 瞎猜 slug(create/mekanism)直接装 |
| **ms_stillcrash**(装了还崩) | `read_crash_report`/`read_instance_log` 诊断 → 处理冲突 | 重复装 sodium/不诊断 |
| **ms_dep**(缺依赖) | `inspect_mod_jar`/查日志 找缺什么 → 补装前置 | 反复装 sodium/不管依赖 |
| **ms_downgrade**(版本不匹配) | 找兼容版本/`install_instance` 建兼容实例/问用户 | 硬装到不兼容实例 |

## 为什么多步比单步更看出差距

单步测"能不能选对工具"(0.8B 也能 67%);多步测"**拿到坏消息/复杂情况怎么办**"——
这需要**保持上下文 + 规划 + 变通**,是 0.8B 和 9B/27B 拉开差距的地方。
**预期:9B/27B 在多步上优势比单步(仅 +2%)更明显。**
